# Roadmap

M3HT4 will grow in deliberate phases. Each phase must produce a usable outcome before the next adds complexity.

  <img src="assets/diagrams/roadmap.svg" alt="M3HT4 phased roadmap" width="940">
</p>

## Phase 0 — Identity and boundaries

**Outcome:** A clear public definition of M3HT4.

- [x] Establish **Modern Hunting Terrain**
- [x] Establish **3 Teams:** Blue, Red, Purple
- [x] Establish **4 Pillars:** Hunt, Detect, Emulate, Train
- [x] Define the framework as more than a home lab or training course
- [x] Define public/private publication boundaries
- [ ] Apply consistent language across GitHub and M3HT4.com

## Phase 1 — Safe validation foundation

**Outcome:** A recoverable and segmented environment capable of producing representative security evidence.

- [x] Virtualization and storage foundation
- [x] Identity-service baseline
- [x] Independent backup and recovery validation
- [ ] Dedicated firewall and segmentation
- [ ] Initial endpoint and network telemetry
- [ ] Controlled test systems
- [ ] Sanitization workflow for public artifacts

## Phase 2 — First complete scenario

**Outcome:** One scenario that demonstrates the entire framework manually.

- [ ] Scenario overview and objectives
- [ ] Representative dataset or event set
- [ ] Blue-team hunt path
- [ ] Detection and visibility notes
- [ ] Red-team emulation plan
- [ ] Purple-team engagement plan
- [ ] Findings and retest templates
- [ ] Public case study

## Phase 3 — Reusable framework model

**Outcome:** A stable structure for adding scenarios without creating an unmaintainable repository.

- [ ] Scenario schema and directory standard
- [ ] Quality and safety checklist
- [ ] ATT&CK references where useful, without copying proprietary content
- [ ] Metadata for team, pillar, difficulty, data source, and expected outcome
- [ ] Contribution workflow
- [ ] Two additional scenarios to validate reuse

## Phase 4 — Interactive web experience

**Outcome:** A simple web application that guides users through proven workflows.

- [ ] Scenario browser
- [ ] Team-perspective selector
- [ ] Guided data exploration
- [ ] Hunt and emulation planning workspace
- [ ] Purple-team engagement builder
- [ ] Exportable notes and plans
- [ ] Clear safety, privacy, and responsible-use controls

## Phase 5 — Curated growth

**Outcome:** Expand usefulness without turning M3HT4 into a giant content warehouse.

- [ ] Small, high-quality scenario library
- [ ] Community feedback and contribution review
- [ ] Portable templates and examples
- [ ] Documentation site and public case studies
- [ ] Optional support or donation model
- [ ] Evaluate sustainable business paths only after product value is demonstrated

## Roadmap rules

A feature should not enter active development unless it:

1. supports a defined team and pillar;
2. improves the proven workflow;
3. can be maintained with realistic time and cost;
4. respects publication safety and legal boundaries;
5. avoids unnecessary vendor lock-in;
6. is simpler than the problem it solves.
